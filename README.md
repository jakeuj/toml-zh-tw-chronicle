# TOML 繁中翻譯爭議：事件全紀錄

獨立繁體中文紀實專題，逐則整理 `toml-lang/toml.io` 的 Issue #97、PR #98 與 Issue #99，以及直接相關的公開外部脈絡，包含原始 Facebook 貼文的 10 則主留言與 8 則回覆，以及作者對 AI 標籤與開源參與心情的後續貼文及其 59 則可讀留言。

**網站：<https://doggy8088.jakeuj.com/>**

本文採中立紀實方向，分開呈現可查核的紀錄、發言者主張與尚無法確認的問題。這不是 TOML 官方網站，也不是兩版翻譯的全面品質認證。資料截點與限制見網站「資料與方法」。網站由 jakeuj 委託 Codex 協作整理、製作與發布；不宣稱完成具名人工語言審校。

## 本機使用

需要 Node.js 22 以上，無外部 npm 依賴。

```sh
npm run build
npm test
npm run preview
```

開啟 <http://127.0.0.1:4173/>。預覽路徑依內容資料中的正式網址設定；目前自訂網域由根目錄提供網站。

正文在建置時寫入 HTML；不執行 JavaScript 仍能閱讀全部內容。JavaScript 增加搜尋、作者／討論串篩選、複製錨點與閱讀位置提示，不在訪客端呼叫 GitHub API。

## 內容與更新

- `data/chronicle.json`：原創繁中轉述、來源 ID、作者、時戳、編輯時間、回應關係、查核註記、歷史補充及狀態事件。
- `data/facebook-comments.json`：原始 Facebook 貼文 18 則可讀留言／回覆的轉述、來源 ID、回覆層級、分鐘精度時間及原始可見文字雜湊。正文不保留原文全文；「作者說讚」與已編輯僅描述擷取時 UI 顯示。
- `data/facebook-followup-comments.json`：後續貼文 59 則。三則僅能確定回覆對象姓名，保留候選清單與限制；唯一可見對應也標示對應依據，不補造父留言 ID。縮排 2 表示回覆中的回覆，不聲稱精確完整鏈長。
- `data/translation-context.json`：俄文 #86、#99 機翻與語系標籤的語意查核，以及 BBC 報導的 AI 翻譯／人工審核流程對照。標示為編輯分析，保留獨立查閱時間，不加入 93 筆留言數。
- `data/coverage.json`：擷取截點、17 個來源物件的對應、原文 SHA-256、六個狀態事件及 PR 提交資訊。空白 review 記入來源覆蓋，與作者同時提交的行內回覆對應，不重複當成有文字的發言。
- 網站只發布整理後資料，不發布研究過程的原文暫存、帳號憑證或私人瀏覽資訊。Facebook 原始貼文已切換所有留言並展開回覆，逐則轉述此次能載入的 18 則；後續貼文另整理 42 則主留言與 17 則回覆，共 59 則。兩篇截點分開記錄，均不宣稱取得平台已刪除、隱藏或受限內容。

登入 GitHub CLI 後可執行唯讀來源差異檢查：

```sh
npm run audit:sources
```

這會完整分頁讀取三串主文、留言、reviews、行內留言與重要 timeline 事件，檢查是否有新增、消失或文字變更，並核對 PR head 與提交清單。不修改內容檔案，也不會自動替新發言生成敘述。若檢查失敗，應重新擷取、逐則核對與修訂，更新清單和截點，再建置及驗證；不可只更新雜湊消除差異。

留言最後編輯時間不是完整修訂歷史。舊快照中的段落有獨立標示，不混入目前可讀留言總數，也不猜測撤除者、原因或精確時間。瀏覽器可讀取來源，不代表公開下載工具同樣可讀；來源可用性可能改變。

## 部署

推送 `main` 後，GitHub Actions 執行靜態建置與完整性測試，將 `dist/` 透過官方 Pages Actions 發布。也可手動觸發同一工作流程。沒有排程、資料庫、追蹤碼或自動抓取讀者資料的服務。

分享圖 `assets/toml-chronicle-cover-v1.png` 為 1200 × 630 PNG；編輯來源是 `scripts/create-cover.py`。重新產圖需要 Pillow，並可透過 `--font` 指定合法可用的繁中字型。圖片已提交，日常建置不需 Python 或系統字型。更新圖像應換檔名並同步 metadata。
