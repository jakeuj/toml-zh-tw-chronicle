# 內容與模板模組化任務

每項預計 30–60 分鐘。只在實際完成並核對相應驗收條件後勾選。

- [x] 1. 建立中英文內容基線：記錄全部紀錄 ID、章節與來源錨點、正文、來源網址、時間與回覆證據，以及現有互動驗證清單。
- [x] 2. 遷移中英文事件導讀與章節開場文案至章節資料，維持目前輸出；為新章節加入翻譯同步檢查。
- [x] 3. 遷移中英文爭點摘要與來源方法文案，對照基線確認引用、限制註記與歷史補充完整保留。
- [x] 4. 抽出共用資料載入、HTML 跳脫與時間格式工具，集中語系介面標籤，保留臺灣／UTC 對照及分鐘精度差異。
- [x] 5. 抽出共用 GitHub／Facebook 紀錄卡與討論串元件，核對六組來源的排序、回覆呈現與證據差異。
- [x] 6. 抽出時間線、章節與頁面外框，讓兩個建置入口使用共用模板；確認資源複製、清理與 sitemap 輸出順序正確。
- [x] 7. 更新內容與中英文完整性測試，驗證文案遷移、固定 ID、來源證據、翻譯同步與無 JavaScript 正文；完成建置及測試。
- [x] 8. 更新 README 並新增專案 AGENTS.md，標示內容位置、來源／翻譯更新分支與驗證方式；以桌面及手機寬度檢查兩種語言的導覽、搜尋、複製與語言切換，核對基線後記錄驗收結果。

## 驗收條件

- 情境：AI 要修訂事件導讀或爭點文字時，從專案指引能定位到對應章節資料，修改正文不必編輯建置程式內的 HTML。
- 情境：修改一個共用紀錄卡模板後，中英文頁面都呈現該變更；兩種語言的內容仍各自從語系資料讀取。
- 情境：讀者停用 JavaScript，兩種語言仍各自包含原有 144 筆紀錄、28 項 GitHub 時間線項目、完整來源與方法。
- 情境：核對遷移前後資料，所有紀錄正文、來源 ID、作者、時間、回覆限制、查核註記與歷史補充都能對應；查核狀態不因重構而改變。
- 情境：讀者開啟既有紀錄錨點、搜尋、篩選、複製連結或切換語言，行為與原有單頁網站一致。
- 情境：中文內容異動但英文尚未複核時，測試仍能指出需要同步，不會因改為共用模板而跳過翻譯檢查。
- 情境：完成 `npm run build` 與 `npm test`，全部檢查通過；提交差異包含本階段檔案，使用者既有修改保持原樣。
