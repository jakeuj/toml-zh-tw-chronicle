# 內容與模板模組化

需求類型：重構。

## 為什麼做

目前來源紀錄已拆成多份 JSON，但事件導讀、爭點摘要、來源方法與部分章節說明仍直接寫在 `scripts/build.mjs`、`scripts/build-en.mjs`。兩份程式各自維護完整頁面模板，更新文字或功能時需要跨內容與 HTML 查找，也可能只修到其中一種語言。

本階段建立清楚的內容位置與共用渲染流程，讓 AI 依更新範圍只讀必要檔案，並讓後續拆頁能重用同一組元件。

## 要改什麼

- 將導讀、爭點與來源方法等編輯文案，依章節移至 `data/editorial/`，英文放在 `data/en/editorial/`。保留既有 `brief.json`、來源紀錄與語意查核資料，不搬動已具明確職責的檔案。
- 每章使用符合實際內容的簡單欄位，例如標題、段落、來源 ID 與限制註記；由渲染器控制 HTML。共用介面標籤集中於語系資料，避免每種語言複製模板，也不建立任意 HTML 的通用內容引擎。
- 抽出共用資料載入、HTML 跳脫、時間格式、紀錄卡、來源討論串、時間線、章節與頁面外框。差異由語系資料與明確參數處理；Facebook 各來源不同的回覆證據仍依原始欄位呈現。
- 保留目前中英文各一頁的輸出、章節次序、原文來源連結、固定 ID、搜尋、語言切換、時間精度與限制說明。
- 保留現行英文 `sourceEditorialSha256` 防護，新增章節資料也須有對應的同步檢查。純格式調整造成既有檔案雜湊改變時，先核對語意與中英文對應再更新雜湊。
- 新增精簡的專案 `AGENTS.md`，指出各類更新應讀的檔案與操作順序，將來源核對、翻譯同步與發布規則連到 README 的權威說明。只有相關更新才需載入的細節放在對應文件。

## 影響範圍

- 新增：`data/editorial/*.json`、`data/en/editorial/*.json`、共用介面語系資料，以及 `scripts/lib/` 下的共用渲染模組。
- 修改：`scripts/build.mjs`、`scripts/build-en.mjs`、`scripts/render-brief.mjs`、`tests/site.test.mjs`、`tests/english.test.mjs`、`README.md`。
- 新增：專案根目錄 `AGENTS.md`，以及驗證新內容結構所需的測試。
- 既有紀錄 JSON 僅在實作確有必要時調整結構，紀錄文字與證據欄位以基線保留。既有 `.gitignore` 修改由使用者持有，不納入本需求。

## 邊界與完成標準

本階段不新增公開頁面或重新擷取來源，不改寫紀錄立場、來源截點或翻譯內容。完成後，編輯一段既有導讀文案能透過章節資料完成；版型修改能同時作用於兩種語言；既有網址、錨點與互動仍可使用。

驗證以內容、證據與可用行為為準，允許無語意差異的 HTML 空白或屬性順序變動。先保存基線的可公開內容與 ID 對照，再逐步遷移；每步保持可建置，避免同時搬動全部內容後才核對。
