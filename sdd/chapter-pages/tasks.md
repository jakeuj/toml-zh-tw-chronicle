## 驗收條件

- 情境：讀者開啟首頁，能先讀懶人包與事件導讀，再依清楚的入口選擇時間線、紀錄、爭點或資料方法，首頁不再直接展開全部 144 筆紀錄。
- 情境：彙整各語言的四個紀錄頁，恰有原本的 144 個唯一紀錄 ID，包含 16 筆 GitHub 與 128 筆 Facebook；28 項 GitHub 時間線完整保留。
- 情境：讀者從爭點分析點選來源紀錄，會到達正確的來源頁與指定 ID；回覆、候選父留言、歷史補充與方法引用均可到達。
- 情境：讀者在全站搜尋輸入只出現在其他來源頁正文或註記的字詞，仍能找到該紀錄；作者與討論串篩選及清除篩選都有效。
- 情境：讀者開啟既有 `/#紀錄ID` 或 `/en/#紀錄ID`，啟用 JavaScript 時到達同語言的新紀錄位置；停用時可從舊入口明確前往該頁，無死連結。
- 情境：讀者在深層紀錄位置切換語言，仍停在相對應的來源頁與同一紀錄 ID；複製連結後重新開啟可定位到該紀錄。
- 情境：停用 JavaScript，兩種語言各頁都有完整靜態正文，紀錄索引可逐一前往每則內容，所有章節與原始來源連結可用。
- 情境：首頁或資料方法頁沒有搜尋控制項時，共用腳本仍正常；未知錨點與返回鍵不造成跳轉迴圈。
- 情境：所有正式頁面的標題、canonical、對應語言與 sitemap 指向正確路徑，來源截點保持原意，深層頁面可載入樣式與腳本。
- 情境：`npm run build` 與 `npm test` 全部通過，桌面／手機及無 JavaScript 驗收完成，紀錄內沒有未處理的內容缺漏或斷鏈；尚未推送或部署。
