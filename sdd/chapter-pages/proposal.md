# 專題拆頁與導覽

需求類型：重構。前置條件：`content-modules` 完成並驗收。

## 為什麼做

目前繁中頁面六個章節約 5.7 萬個可見字元，逐則紀錄約占 78%。讀者雖可透過錨點跳轉，首頁仍同時承擔導讀、查資料、爭點分析與來源方法等不同用途。

本階段依閱讀目的與來源拆頁，讓首頁保留事件脈絡，完整紀錄則有穩定入口；全站搜尋與舊分享連結仍能找到原本的內容。

## 要改什麼

### 公開頁面

| 繁中路徑 | 內容 |
| --- | --- |
| `/` | 懶人包、事件導讀、既有後續回應與各章入口 |
| `/timeline/` | 完整 GitHub 時間線、涵蓋範圍與時間精度說明 |
| `/records/` | 六組討論串入口、全站紀錄搜尋，以及無 JavaScript 可用的紀錄連結清單 |
| `/records/github/` | #97、#98、#99 共 16 筆紀錄及相關歷史補充 |
| `/records/facebook-original/` | 原始 Facebook 貼文的 18 筆紀錄 |
| `/records/facebook-published/` | 另行發布貼文的 51 筆紀錄、計數差額與查核限制 |
| `/records/facebook-followup/` | 後續貼文的 59 筆紀錄與回覆限制 |
| `/analysis/` | 六項爭點對照、語意查核與仍待確認的問題 |
| `/sources/` | 原始連結、資料來源、方法、各來源截點與權利說明 |

英文在各路徑前加上 `/en`，保留相同的章節與紀錄 ID。每個內容區塊有一個主要歸屬頁；首頁摘要與搜尋結果連回該頁，完整紀錄不另建重複版本。

### 內容連結與舊網址

- 由同一份路由表與內容 ID 對照表產生站內連結、搜尋結果、語言切換與舊錨點入口。對照範圍包含原有的章節、紀錄、討論串、語意查核、歷史補充及方法錨點。
- 頁面內保留原有紀錄 ID，跨頁引用產生正確路徑與 fragment；複製功能輸出目前紀錄歸屬頁的網址。
- 根目錄與 `/en/` 遇到已移動的舊錨點時，啟用 JavaScript 可導向正確語言的新網址；使用替換歷史紀錄的導向，避免返回鍵在新舊頁面反覆跳轉。
- 停用 JavaScript 時，舊入口提供可到達的靜態對照與清楚的新頁連結；保留未移動章節的原地定位。未知錨點留在目前頁面，不猜測目的地。

### 搜尋與互動

- 建置時由既有資料為兩種語言各產生搜尋索引，包含紀錄 ID、歸屬網址、作者、討論串，以及目前搜尋涵蓋的標題、時間、正文、脈絡與註記。
- `/records/` 提供關鍵字、作者與討論串篩選，結果連到完整紀錄。各紀錄頁提供前往全站搜尋的入口；不以只搜尋目前頁面取代原本的全站功能。
- 共用腳本依頁面上實際存在的控制項初始化，讓首頁、時間線與來源頁不因缺少搜尋表單而出錯。閱讀進度依目前頁面計算。
- 全部正文仍由靜態 HTML 輸出。停用 JavaScript 時可循章節與紀錄索引閱讀所有內容，搜尋表單則附清楚的功能說明。

### 頁面識別與建置

- 每頁提供符合內容的標題、description、自身 canonical、雙向對應語言 hreflang、Open Graph 網址及共用分享圖。所有正式內容頁列入 sitemap。
- sitemap 日期依頁面實際依賴的內容／來源截點推導；重構不把舊來源截點改成新的查核時間。
- 延用靜態建置與 GitHub Pages。資源路徑、預覽服務與中英文深層網址均支援正式網址所設定的基底路徑。

## 影響範圍

- 新增：`scripts/lib/` 下的路由與 ID 歸屬對照模組、頁面渲染模組，以及對應測試。
- 修改：中英文建置入口、`assets/app.js`、必要的 `assets/style.css` 導覽規則、README 與專案 AGENTS.md 的內容位置指引。
- 調整：現有單頁測試改為跨頁驗證，保留原有內容與來源覆蓋的檢查強度；新增深層路徑、舊錨點、語言切換與搜尋驗收。
- 產生：`dist/` 內的多頁 HTML、語系搜尋索引、舊錨點對照與 sitemap；不手動編輯建置產物。

## 邊界與完成標準

本階段不更換框架、不新增後端或外部搜尋服務，不新增來源擷取或自動生成敘述。既有來源 JSON 按來源分組保留，不以每則留言建立一個檔案或一個公開頁面。

完成後首頁可快速理解事件；讀者能按來源查閱全部紀錄，從搜尋結果或舊分享連結到達正確內容，並在相同位置切換語言。完整性以跨頁彙整後的唯一紀錄 ID 與正文對照為準，不能因首頁不再包含全部正文而刪除覆蓋檢查。

本計畫交付至本機可驗收成果；推送 `main` 會觸發現有自動部署，應在另外明確要求發布時才進行。
